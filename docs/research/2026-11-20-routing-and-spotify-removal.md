# IRA routing and Spotify removal

Implemented on 20 November 2026 following the user-approved gate review.

## Result

Spotify's four dedicated voice tools, three compiled adapters, procedural package,
player/browser modules, aliases, current prompt instructions and active evaluation
drivers have been removed. Explicit generic browser/app requests remain supported.
The current task and actual target determine admission; media cannot be substituted
for Microsoft research or another unrelated request.

Default admission uses established deterministic task fit before optional semantic
judgment. Missing clients no longer create unconditional permission. Authoring
operations require a current request; stopped, stale and uncertain actions remain
protected. Active requests renew default execution checkpoints without repeatedly
asking the user to authorize the same task.

The skill library now has canonical decisions, validated input provenance, package
digests including supporting files, reviewed automatic eligibility, and explicit
validated one-time execution. Adaptive runs have immutable, redacted history and
verified-only learning. Replaced tasks and edited definitions retire stale plans.
The dashboard exposes actual adaptive running/Stop state and one-time eligibility.

The research procedure records actually read relevant sources and verifies its
source-backed completion. User-specified depth and source counts override defaults.
Loading, navigation, partial findings and verified completion remain distinct.

## Evidence and verification

The original enabling defect was reproduced with admission-only probes: a Microsoft
request received unrelated Spotify/navigation/input permits. Recorded folder tasks
also selected Spotify. The exact user-reported Microsoft playback incident was not
captured; available Microsoft journal records showed relevant navigation and reads.

All automated host/provider checks used inert boundaries or isolated fixtures.
Regression cases include quoted and negated commands, explicit compound actions,
research text containing media keywords, timeout after navigation commits, changed
support files after validation, stopped/replaced tasks, real exported research
navigation/read/status/completion, post-closure history, and canonical UI run control.

The pre-change targeted baseline passed 150 tests with one skip. The final stable
Python suite passed **1,645 tests with 58 skips**. All source and test files passed
Ruff, and the patch passed `git diff --check`. The final dashboard suite passed
**402 tests across 31 files**; type checking and the production build passed.

The deterministic admission helper was separately measured over 1,000 offline calls:
median 0.0276 ms, p95 0.0351 ms. This is not voice or end-to-end latency. The installed
LiveKit CLI 2.13.2 has no `agent simulate` command, so added simulation scenarios were
not executed through that CLI. Live provider/audio behavior remains unmeasured.

## Preservation

The original working tree was copied into an isolated checkpoint before edits.
Only changes after that checkpoint are eligible for source update, with original
file hashes checked for concurrent edits. Existing personal facts, journal/audit
evidence, browser profiles, credentials and unrelated working changes are preserved.
Retired operating-memory recipes are migrated through locked/revision-checked APIs;
raw private inputs are excluded from committed reports and procedural run evidence.
